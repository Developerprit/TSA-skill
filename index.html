What it does

它解决什么问题

每次「开发 agent」都从零写循环、工具注册、记忆、调度，既重复又易错。TSA-skill 把已验证的 ThinkStack 架构作为默认值，agent 只需关注业务扩展点。

默认架构，而非可选建议

只要用户意图是「开发 / 搭建 agent 应用、智能体、多 agent、agent 工具/记忆/调度」，技能即被触发，强制以 ThinkStack 为底座，并给出精确的执行步骤与代码范式。

本地优先获取

优先搜索本地 ThinkStack；找不到才 git clone https://github.com/Developerprit/ThinkStack.git。

思考/行动/观察前后钩子 + 自定义 工具/记忆/调度器/Agent，单扩展异常被沙箱隔离。

Architecture

ThinkStack 四层架构

所有组件经统一 ThinkStack Expand API 对外开放。模型无关：Agent.think() 只依赖可插拔的 Reasoner 抽象，内置 EchoReasoner 占位，接入真实模型只需实现一个子类。

Core 层

ThinkStack（主入口）· Agent · Tool · Memory · Scheduler · Config · Reasoner · errors

Expand API 层

@expand_hook · register_extension · ExpandHook · ExtensionHandle · ExtensionRegistry

Extension 层

独立 .py 扩展文件，importlib 安全加载，严禁 eval/exec

Runtime 层

9635 REST API（SSE/工具/记忆/Markdown）· webrun 自带浅色/深色 Web 控制台

Execution logic

执行逻辑

  1. 获取 ThinkStack 本体

    本地路径优先（工作区 / E:\PC\ThinkStack / ~/ThinkStack / 已安装），缺失则 git clone，先验证仓库存在性。

  2. 澄清需求

    仅在意图模糊时问：agent 类型、是否接真实模型、记忆是否持久化。

  3. 选择扩展点

    加能力→HOOK_CUSTOM_TOOL；换记忆→HOOK_CUSTOM_MEMORY；自定义调度→HOOK_CUSTOM_SCHEDULER；新 Agent→继承 Agent；插逻辑→HOOK_*_THINK/ACTION/OBSERVE；接模型→实现 Reasoner。

  4. 组装入口

    ThinkStack(config) → register_extension → start → run_agent → shutdown；对外服务用 run.py（9635）。

  5. 验证交付

    import 校验、扩展加载、跑通循环、pytest；中英双语 README、英文 CLI、Available License、默认上传 Developerprit 仓库。
